# SOLVIA｜法人運営

既存の現場管理と並存する個人用プロトタイプ。`npm run dev` 後、`http://localhost:3000/corporate/` を開く。最初は「添付テンプレートを確認」→項目対応と件数を確認→取り込み。独立デモは別領域。

## Excelの確認結果

全9シートの入力項目・入力規則・注意書きと7個の数式を確認し、原本を変更せず `template.xlsx` に保存。取り込み時の原本もIndexedDBに保存しSHA-256を記録する。

元の数式は準備の完了数・未完了数・不要を除く進捗率、事業場の件数・受託中件数・点数合計・契約料合計。アプリでは数式を実行せず意味をJavaScriptに移植し、未入力と確認不足を区別する。全項目不要の分母0は未確認。Excel内に法令点数の算定式はなく、上限・点検頻度・必要経験を推定しない。全シートの注意書き、元の数式は画面から参照可能。

## 実装

- 本部の進捗・人材負荷・期限・装備・不足情報から根拠一覧へ移動。
- 25項目の状態・担当・期限・成果物・確認記録・依存関係・不要理由。依存先未完了と循環を検査。
- 人材・事業場・装備の登録編集、カード／表、タップによる担当者・代務者配置。資格等の確認記録と自己申告の得意分野を区別。
- 点検予定の月間カレンダー／一覧、報告・是正・実施日の別管理。必要機器の時間帯重複・数量・校正期限を確認。1予定につき選択機器1台の割当。
- 緊急対応の入力・経過追記、文書・参考資料の編集。BESS26項目は原本項目一覧であり、訪問ごとの実績票ではない。
- 実務コピーの計画を最大20件保存。現場・人材・機器追加、基準日変更、確認済み点数／記載値の仮計算・契約料・作業／移動時間・不足情報を比較。費用未入力のため利益は計算しない。
- Excel再取込プレビューで追加・更新・手入力保護を表示。既存行を削除せず、UUID・配置・変更したメモを維持。名前だけの自動配置はしない。原本の識別番号を変更すると新規扱いになるのでプレビューで確認する。
- 原本・実務・計画・比較元・デモを含むJSON全体保存／復元。原本ハッシュ・データ形式を検証して一括復元。同時編集の競合は保存を拒否して通知。

## 保存構造

`schema.js` が9種類のフィールドとExcel列対応、`importer.js` がローカルxlsx解析、`model.js` が確認・集計・計画・取込保護、`storage.js` が永続化、`app.js` が画面操作。人材・現場・機器・記録にUUID。元シート・元行・原本ID、取込値と手入力変更フラグ、確認根拠・確認日・確認先を保持。

法人運営はIndexedDB `solvia-corporate-v1`。既存現場管理のlocalStorage `nakadori-desk-v1` を読み書きしない。法人運営バックアップは既存現場管理のバックアップとは別。ブラウザデータ削除・端末変更に備え、定期的にJSONを端末外に保存する。サーバー保存・端末間同期・自動バックアップは未実装。

Excelは5MB・展開30MB・500エントリまで。見出し変更や不足シートは取込停止。外部参照やマクロを実行せず、数式セルはキャッシュ値の未検証を通知。必要に応じExcel側で再計算してから取り込む。原本保管・SHA-256検証のためHTTPSまたはlocalhostで利用する。

## 人物の歩行・停止・作業の調整

検証用に固定拡大表示の `preview/choreography.html` を追加。これは動作を見分けるための確認画面で、本アプリで自動ズームする機能ではない。`test:world` で待機・歩行・停止・計器確認・しゃがみ、停止設定・端末の動き削減・モーダル停止・離脱時の片付け・保存データ不変を確認。単体テストでは障害物範囲と通路、作業中の位置固定、歩行の向き、周期境界と車の停止／後退の連続性、時間差と待機率を検証。

制限：建物や設備の背後を歩く経路は設定せず、前面の通路内を使う。奥行きは足元位置の描画順で扱い、任意の障害物の自動経路探索や複雑な遮蔽マスクは未実装。Safari実機の長時間負荷は未検証。装飾の待機／作業は実務状態ではない。
